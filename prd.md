Analisis & Rencana Eksekusi Teknis: StockFlow (Mini ERP Module)Dokumen ini berisi analisis menyeluruh terhadap spesifikasi technical test StockFlow, strategi penanganan konkurensi data, serta alur pengerjaan bertahap (step-by-step roadmap) dengan alokasi waktu total 6–8 jam pengerjaan.1. Analisis Ringkas & Poin Kunci Penilaian1.1 Parameter UtamaDomain Aplikasi: Modul ERP mini untuk manajemen produk, penyesuaian stok (stock adjustment), dan pencatatan pesanan penjualan (sales order).Teknologi: Go + PostgreSQL (Backend) & React + TypeScript via Vite (Frontend).Batas Waktu: 1 Hari Kalender (dikumpulkan sebelum 23:59 GMT+7).Estimasi Fokus: 6–8 jam kerja efektif.1.2 Hirarki Prioritas EvaluasiKeamanan Data & Konkurensi: Penanganan mutasi stok tanpa desimal/float, mencegah stok negatif (overdraw) pada pesanan serentak (concurrent orders).Kebenaran Lintas Stack (Cross-Stack Correctness): Pemrosesan error kustom (seperti 409 INSUFFICIENT_STOCK dan 409 PRODUCT_HAS_HISTORY) dari database/backend yang tersaji dengan jelas pada antarmuka frontend.Praktik Rekayasa Perangkat Lunak (Engineering Practices): Docker compose satu perintah, unit test & concurrency test, seed data, commit Git yang bertahap, serta dokumentasi README.md.Visual & UI Polish: Tampilan antarmuka yang bersih dan fungsional (bukan fokus utama styling rumit).2. 2.2 Model Data & Relasiproducts: id (PK), sku (UNIQUE), name, price (INTEGER $\ge 0$, mata uang IDR), stock (INTEGER $\ge 0$), is_active, created_at.stock_movements: id (PK), product_id (FK products.id), type ('in' | 'out'), qty ($> 0$), note, created_at.sales_orders: id (PK), customer, status ('CREATED' | 'CANCELLED'), total, created_at, cancelled_at.sales_order_items: id (PK), order_id (FK sales_orders.id), sku (FK products.sku), qty ($> 0$), unit_price.2.3 Strategi Konkurensi Stok & Transaksi AtomikAturan Transaksi Pesanan:Pengurangan stok seluruh item dilakukan secara atomik dalam 1 Database Transaction (BEGIN ... COMMIT/ROLLBACK).Apabila salah satu SKU kekurangan stok, seluruh transaksi harus di-rollback (HTTP 409) dan tidak boleh ada stok yang terpotong.unit_price diambil langsung dari tabel products saat pemrosesan server (klien tidak boleh mengirimkan harga sendiri).Pencegahan Race Condition:Dilarang: Pola SELECT stok, cek di aplikasi, lalu UPDATE.Pendekatan Wajib: Menggunakan Row Lock pada query SELECT (SELECT stock FROM products WHERE sku = $1 FOR UPDATE) ATAU penguncian langsung saat instruksi UPDATE (UPDATE products SET stock = stock - $1 WHERE sku = $2 AND stock >= $1).3. TAHAP 1: Infrastructure & Database Setup (~60 Menit)Langkah 1.1: Inisialisasi Repositori & Docker Compose (~30 min)Buat folder proyek stockflow/ beserta sub-folder backend/ dan frontend/.Buat file docker-compose.yml untuk menjalankan container PostgreSQL.Konfigurasikan volume mount agar skrip SQL migrasi dan seed dieksekusi otomatis saat PostgreSQL pertama kali menyala.Langkah 1.2: Skema DB & Seed Data (~30 min)Tulis skrip DDL SQL (schema.sql) sesuai tabel spesifikasi dengan semua pengecekan constraint (CHECK (price >= 0), CHECK (qty > 0), CHECK (stock >= 0)).Tulis skrip seed.sql berisi:Minimal 12+ produk realistis dengan variasi stok ($\le 10$ untuk pengujian low stock, stok aman, dan produk tidak aktif).Beberapa sampel transaksi pesanan beserta riwayat pergerakan stoknya.TAHAP 2: Backend Development - Go API (~2.5 Jam)Langkah 2.1: Setup Project & Structure Go (~20 min)Inisialisasi modul Go (go mod init stockflow-backend).Buat struktur folder Go idiomatik:cmd/server/main.gointernal/config/internal/model/internal/repository/internal/handler/internal/middleware/Langkah 2.2: Implementasi Handler Produk & Stok (~60 min)GET /api/products:Paginasi (page, limit), pencarian case-insensitive (ILIKE) pada SKU/nama.Sertakan field last_movement_at (derived via LEFT JOIN / subquery dari stock_movements).POST /api/products & PUT /api/products/{id}: Validasi SKU unik, nama wajib, harga $\ge 0$.DELETE /api/products/{id}: Cek keberadaan riwayat pergerakan di stock_movements. Jika ada, return HTTP 409 {"error":{"code":"PRODUCT_HAS_HISTORY"}}.POST /api/products/{id}/stock:Jalankan dalam DB Transaction.Catat baris di stock_movements.Update stok di products. Jika stok kurang pada tipe 'out', kembalikan HTTP 409 INSUFFICIENT_STOCK beserta sisa stok.GET /api/products/{id}/movements: Ambil riwayat mutasi berdasarkan waktu terbaru.Langkah 2.3: Implementasi Transaksi Order & Konkurensi (~70 min)POST /api/orders:Validasi Input Awal: SKU terdaftar, qty > 0, tidak ada SKU duplikat dalam 1 request, item tidak kosong (return 400).Buka Transaksi DB (tx.Begin()):Untuk setiap item, eksekusi row lock SELECT id, price, stock FROM products WHERE sku = $1 FOR UPDATE.Jika stok $< \text{qty request}$, Lakukan tx.Rollback() dan kembalikan HTTP 409 {"error":{"code":"INSUFFICIENT_STOCK", "sku":"...", "available": n}}.Hitung total harga server-side menggunakan unit_price dari DB.Kurangi stok produk dan simpan record ke sales_orders & sales_order_items.Catat pergerakan stok tipe 'out' di stock_movements.Commit transaksi tx.Commit().POST /api/orders/{id}/cancel:Buka transaksi DB, kunci baris order (FOR UPDATE).Jika status sudah 'CANCELLED', return 409.Kembalikan stok untuk semua item order terkait, catat pergerakan stok tipe 'in', dan perbarui status order menjadi 'CANCELLED'.GET /api/orders/{id}: Tampilkan detail order beserta item dan statusnya.TAHAP 3: Pengujian Backend / Testing (~45 Menit)Langkah 3.1: Unit Test Logic & Repositori (~25 min)Buat unit test Go untuk kasus penolakan insufficient stock: pastikan transaksi di-rollback penuh dan tidak ada data yang tersimpan.Buat unit test untuk happy path: pastikan penambahan mutasi stok memperbarui nilai stok produk dengan benar.Langkah 3.2: Concurrency Test (~20 min)Buat integration/concurrency test (go test -race):Jalankan beberapa goroutine secara berbarengan yang mencoba mengurangi stok untuk SKU yang sama secara berlebihan.Pastikan sisa stok tidak pernah bernilai negatif ($< 0$) dan jumlah order yang berhasil sesuai dengan ketersediaan stok awal.TAHAP 4: Frontend Development - Setup & Client (~60 Menit)Langkah 4.1: Setup Vite & TypeScript Strict (~20 min)Buat proyek React via Vite: npm create vite@latest frontend -- --template react-ts.Atur tsconfig.json agar berjalan dalam mode strict.Konfigurasikan proxy pada vite.config.ts untuk mengarahkan /api ke server Go (http://localhost:8080).Langkah 4.2: Tipe Data Domain & API Client Modul (~40 min)Buat file src/types/api.ts yang berisi seluruh interface domain data (Product, StockMovement, SalesOrder, ApiErrorEnvelope, dll.).Buat API Client terpusat di src/services/api.ts:Mengelola seluruh operasi fetch.Menangani parsing struktur error kustom (HTTP 400, 409, 500) agar mudah dikonsumsi oleh komponen UI.TAHAP 5: Antarmuka UI & Integrasi End-to-End (~1.5 Jam)Langkah 5.1: Halaman Produk & Summary Cards (~40 min)Summary Cards: Tampilkan total produk, produk aktif, total nilai stok ($\sum \text{price} \times \text{stock}$), dan jumlah produk low-stock ($\le 10$).Tabel Produk:Tampilkan SKU, Nama, Format Harga (contoh: Rp 1.234.567), Stok, Badge Status, Pergerakan Terakhir (misal: "2h ago"), dan Tombol Aksi.Fitur Filter: All / Active / Inactive / Low stock ($\le 10$).Fitur Pencarian: Implementasikan pencarian dengan debounce.State Handling: Tampilkan kondisi Loading, Empty, dan Error dengan tombol Retry.Langkah 5.2: Modal Adjust Stock & Flow Order (~50 min)Modal Adjust Stock:Form pilihan arah (in/out), jumlah, dan catatan.Nonaktifkan tombol submit saat pemrosesan berlangsung.Tangkap response HTTP 409 INSUFFICIENT_STOCK dari backend dan tampilkan stok yang tersedia secara jelas di UI.Flow Buat Order:Form pembuatan pesanan (pilih nama pelanggan + item produk & qty).Tangkap HTTP 400 (error validasi) atau HTTP 409 (stok kurang pada SKU tertentu) dan sorot input SKU yang gagal secara presisi.Detail Order & Pembatalan:Halaman/Modal detail order beserta tombol konfirmasi pembatalan.Setelah pembatalan sukses, pastikan data stok di tabel produk diperbarui secara otomatis.TAHAP 6: Dokumentasi, Git, & Deliverable Final (~45 Menit)Langkah 6.1: Pengujian Unit Frontend & Integrasi Lokal (~20 min)Tulis unit test sederhana menggunakan Vitest untuk fungsi utilitas (formatting harga IDR, validasi form, atau kalkulasi summary).Jalankan docker compose up pada lingkungan bersih untuk memastikan database, migrasi, dan seed data berjalan otomatis tanpa kendala.Langkah 6.2: Finalisasi README.md & Git Commit History (~25 min)Pastikan repositori memiliki riwayat commit yang rapi dan terstruktur sepanjang pengerjaan.Tulis README.md mencakup:Instruksi Jalankan Aplikasi: Langkah persis untuk menjalankan aplikasi ($\le 5$ menit).Contoh Perintah Curl: Sampel request untuk menguji endpoint API utama.Keputusan Desain Teknis: Penjelasan strategi penanganan konkurensi data.Rencana Pengembangan Selanjutnya (What I Would Do Next): Poin perbaikan jika diberikan waktu lebih.Estimasi Waktu Jujur: Rincian durasi waktu pengerjaan.4.
